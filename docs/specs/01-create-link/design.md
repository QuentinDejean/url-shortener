# Design — 01 Create link (`POST /links`)

Implements the requirements in [requirements.md](./requirements.md).

## Data model

Table `links` (migration `0001_create_links`):

| Column | Type          | Rules                                                        |
|--------|---------------|--------------------------------------------------------------|
| `id`   | `bigint`      | Primary key, `GENERATED BY DEFAULT AS IDENTITY`              |
| `code` | `varchar(10)` | `NOT NULL`, `UNIQUE`                                         |
| `url`  | `text`        | `NOT NULL`, `CHECK (char_length(url) <= 2048)`               |

The 2048 limit is enforced twice: Zod at the API edge and a CHECK constraint in the database. `id` uses Drizzle's `bigint({ mode: "number" })` so the API can return it as a JSON number.

## API contract

```
POST /links
Content-Type: application/json

{ "url": "https://example.com/some/long/path" }
```

| Status | Body                                                      | When                                                     |
|--------|-----------------------------------------------------------|----------------------------------------------------------|
| 201    | `{ "id": number, "code": string, "url": string }`         | Link created                                             |
| 400    | `{ "error": { "code": "validation_error", "message": string } }` | Missing/invalid `url`, non-http(s) scheme, > 2048 chars, malformed JSON |
| 415    | Fastify default                                           | Request body is not JSON                                 |
| 500    | `{ "error": { "code": "internal_error", "message": string } }`   | 3 code collisions in a row, or unexpected DB failure  |

Code generation: 7-char Base62 (`A-Za-z0-9`) via `randomInt` from `node:crypto`, length fits `varchar(10)` with headroom. Insert is `INSERT ... ON CONFLICT DO NOTHING RETURNING id, code, url`; a `null` row means the code collided, and the route retries (max 3 attempts) before returning 500.

**URL normalization (decided after the step-2 review):** the stored URL is `new URL(url).href` of the submitted URL — canonical, absolute, and percent-encoded to ASCII. This guarantees every stored URL can be emitted as a `Location` header (a raw Unicode path like `https://example.com/你好` would make Node reject the header with `ERR_INVALID_CHAR`). Normalization happens in the Zod schema (`.transform().pipe(z.string().max(2048))`), so the 2048 limit is applied to the normalized value that will actually be stored, and oversize normalized URLs get a `400`.

## Affected files

- `src/db/schema.ts` — `links` table definition
- `migrations/0001_create_links.sql` — generated migration
- `src/lib/code.ts` — pure `generateCode()` (7-char Base62, `node:crypto`)
- `src/db/links.ts` — `insertLink()`; the only DB access for this feature (returns the row or `null` on conflict)
- `src/routes/links.ts` — `POST /links` handler (Zod parse → generate → insert, retry loop)
- `src/server.ts` — registers the routes; error handler maps Fastify's `statusCode === 400` errors (malformed JSON) to `validation_error`
- `biome.json` — ignore the generated `.amp/` directory

## Edge cases

- **Code collision** — retry with a fresh code; collisions are detected via the empty `RETURNING` set (no unique-violation exception path exists because the insert is conflict-nothing).
- **URL exactly 2048 chars** — accepted (Zod `max(2048)` and CHECK are both `<=`).
- **Non-http(s) absolute URLs** (`ftp://`, `mailto:`) — rejected: Zod pins the protocol to `https?`; bare `z.url()` would accept any scheme.
- **Malformed JSON** — Fastify raises a parse error with `statusCode === 400`; the error handler maps it to `validation_error` instead of the catch-all 500.
- **Unexpected DB failure** — propagates to the error handler → 500 `internal_error`; it is not treated as a collision.

## Test plan

- `test/code.test.ts` — pure generator: length, charset, custom length.
- `test/links.test.ts` — stubbed DB (`vi.mock` of the DB-query module, `generateCode` stubbed deterministic), exercised through `app.inject`: 201 happy path; 400 for missing/malformed body, non-http(s) URLs, > 2048 chars; collision retry (asserts a second distinct code was attempted); 500 after 3 collisions; 500 on DB failure. No Postgres involved.
- `test/links.db.test.ts` — real Postgres (requires the local database and migrations): end-to-end POST through `inject`, and a duplicate-code insert proving the unique constraint + conflict-nothing behaviour. Cleans up only the rows it created, so it is safe against a database holding other data.

## Decisions (resolved during review)

1. **Server-generated codes** (7-char Base62) rather than client-supplied — custom codes are out of scope for now.
2. **Exhausted collisions return 500**, not 409 — a collision is an internal generation event, not a client conflict.
3. **Response is `{ id, code, url }`** — no resolved `shortUrl` field until the redirect feature exists.
